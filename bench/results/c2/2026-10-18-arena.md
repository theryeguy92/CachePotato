# The arena: bit-identical, and it does not pay at engine level

**Date:** 2026-10-18 · **Branch:** `feat/qwen3-30b-a3b` · **Status: measured, negative, off by default.**

The region arena was the remaining lever: let the pager own the bytes — one `pread` of exactly the
region into a budgeted buffer, eviction recycles the buffer, the block reads from RAM. On a single
tensor that primitive is strictly better than what the engine does today. At engine level it is not,
and the reason is the interesting part.

## The primitive was better (measured first, `scratch/ra_probe.c`)

One `matmul_wx_q8` over a 1.67 MB expert tensor, cold:

| read mechanism | bytes read | time |
|---|---:|---:|
| fault-around (today) | 5.5–9.6 MB (3.3–5.8×) | 12–18 ms |
| `MADV_RANDOM` | 1.68 MB (1.00×) | 24–25 ms |
| **`pread` into a buffer (arena)** | **1.68 MB (1.00×)** | **6–13 ms** |

So the arena primitive wins on both axes, which is why it was built rather than argued about.

## What was built

`CP_ARENA=1`: a miss is `malloc` + `pread` of the region; eviction frees the LRU buffer; the block and
driver read through `pager_region_get(id)`, which returns the buffer address (or the mapping address
when the arena is off), so there is one code path either way. Two details that make it honest:

- **pinned regions still count against the budget**, and a region larger than the whole budget is
  read through the mapping rather than silently over-allocating;
- **the page-cache pages are dropped after each `pread`** (under `CP_PAGER_SYS`), because otherwise
  the page cache becomes a shadow cache the budget does not count and a "miss" would be a memcpy.

Bit-identity holds and is gated: the C1 tool now also runs a tight-budget arena pass and requires it
to equal the unpaged run byte for byte. It does.

## At engine level it loses (8 GB, 2 reps, 32 tokens; logical counters identical to the non-arena run)

| config | regions/tok | MB fetched | evict/tok | **physical MB/tok** | ms/tok | tok/s |
|---|---:|---:|---:|---:|---:|---:|
| 8 GB, mapping | 108.3 | 542.9 | 104.4 | **1013.7 ± 14.4** | 6805 ± 278 | 0.147 |
| 8 GB, **arena** | 108.3 | 543.2 | 104.5 | **1135.5 ± 13.1** | 6949 ± 287 | 0.144 |
| 2 GB + pinned, mapping | 384.0 | 1925.2 | 386.1 | **2110.1 ± 4.0** | 10008 ± 74 | 0.100 |
| 2 GB + pinned, **arena** | 384.0 | 1925.2 | 384.0 | **2127.2 ± 12.9** | 10167 ± 306 | 0.098 |

The logical counters are identical to within a region (the policy is unchanged); the physical bytes
are *higher*, and it is slightly slower. The arena removed the fault-around over-read and gained
nothing.

## Why, and what it teaches

- **Region granularity becomes read granularity.** With the mapping, touching one row of the 330 MB
  `embed` table reads one page (plus fault-around). With the arena, touching it reads the whole
  region. The same applies to any region the model uses partially — and the file's region table
  declares `embed` as one region because the converter emits one region per tensor. A pager that
  owns the bytes exposes that mismatch instead of hiding it behind page faults.
- **The over-read was not pure waste.** Fault-around reads into *neighbouring* regions, and a
  neighbouring region is often the next thing needed; the page cache then serves it. The arena reads
  exactly the requested region and discards that incidental locality.
- So the two measurements agree once the unit is right: per *tensor* the pread is better, per
  *region-as-declared* it is not, because the region is not the access unit.

## What this closes

The arena as a drop-in read mechanism. It is committed, gated (bit-identity at a tight budget), and
**off by default**. Adopting it would require the file to declare access-sized regions — per-row
regions for `embed`, and a region size chosen against the read-latency curve rather than against the
tensor layout. That is a *layout* change, and this project has now measured that layout changes are
free to make and must be measured rather than assumed:

- co-selection grouping (2 experts/region): exact, and slower at 8 and 11 GB — the pairs were
  co-selected only 11.2% of the time;
- region-sized reads without a declared access unit: exact, and slower, because one region is not one
  access.

The two negatives point the same way: **the lever is the region definition, not the read syscall.**
The next useful layout experiment is `embed` by row (a 330 MB region touched for 4 KB) plus experts
left at one per region, measured with the same cold/interleaved protocol. That is a converter change
and one measurement arm, and the machinery for both is already gated.

## Limits

One prompt, 32 tokens, 2 reps, one disk; the physical numbers carry ±12% across sessions. The 8 GB
comparison is the load-bearing one; the 2 GB arena rows are recorded for completeness.
